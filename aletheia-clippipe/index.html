Virtual terminal registry

Device directory

One persistent identity per AI device. Browser chat URLs are reconnection bookmarks, not network sockets, login credentials or permission to read chat contents.

All three terminals are manual. No remote AI is connected, and the directory does not open or control browser tabs automatically.
Packet standard

ALETHEIA/1 envelope

Readable over a clipboard, serial terminal, editor or network transport. Fields are metadata; everything after the blank line is untrusted message data.

HELO ALETHEIA/1
ID msg-0001
FROM aletheia-manager-001
TO agent-a
TASK task-001
TYPE TASK
SEQ 1

Inspect the supplied source file.
Return findings and unresolved questions.
EOM

ACK receipt, EOM end of message, DONE task complete, PAUSE work checkpoint, ERROR failure.

Network architecture

Local today · tunnel later

Phase 1: Manual switchboard

127.0.0.1:8765 → local Python operator → SQLite → copy/paste to supported AI chats. Works with a changing/shared public IP because there are no inbound internet connections.

Phase 2: Opt-in private connectivity

Agent → authenticated HTTPS relay or Tailscale → persistent operator identity. Outbound tunnels can traverse CGNAT; TLS protects traffic, while authentication and authorization control who can send commands.

Phase 3: Compatible agents

A2A adapters for agent-to-agent jobs, MCP tools for approved local operations, and signed or authenticated task manifests. No automatic external actions without user approval.

No remote tunnel, port forwarding, SMTP or browser automation is implemented in this prototype. Exposing the present localhost server publicly would be unsafe.
