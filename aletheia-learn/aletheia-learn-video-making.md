# Aletheia Learn – Make a Short Video

[Aletheia Protocol](https://github.com/KarstenEvans/aletheia-protocol) · [Thalia Protocol](https://github.com/KarstenEvans/thalia-protocol/blob/main/THALIA_PROTOCOL.md)

All Markdown created by this lesson must include the two links above near the beginning. Aletheia governs evidence, provenance and uncertainty; Thalia offers optional considered humour, never invented facts.

**Goal:** Make a usable 15-, 30- or 60-second video plan from a real idea, with only the equipment actually available. **Status:** This lesson can produce a production pack; it does not render, caption, upload or publish footage without a real compatible tool, files and explicit human approval.

**Parent:** [Aletheia Learn](aletheia-learn.md). Use its hint ladder, accessibility options, teach-first lesson sequence, AI-independent handoff and user control. The broader [Content Repurposer Skill](https://github.com/KarstenEvans/11-aletheia-enabled-workflow-skills/tree/main/skills/content-repurposer) can turn an *existing* article/transcript into platform-specific drafts. This lesson teaches the *creation process*. Do not turn this into a second publisher.

## Start, for any AI tutor

If the learner asks to START or to create a short video:

1. **Welcome briefly.** Explain the workflow and show a tiny worked example before asking a question. Do not start with a quiz.
2. Ask only for the essentials not already supplied: the topic, intended viewer, approximate length (15 / 30 / 60 seconds), and what equipment or footage is available. If some are missing, use explicit provisional defaults (30 seconds, phone only) and invite correction.
3. Teach one stage at a time and show a short example. Let the learner attempt a step where useful. Honour HELP, NEXT, BACK, EXAMPLE, SKIP and ANSWER NOW; ANSWER NOW gives the complete pack and labels it AI-assisted.
4. Keep the production pack consistent across stages. For factual claims, use trusted sources if available or mark NEEDS CHECK. Never invent first-person experience, quotations, statistics, equipment, footage, images or media rights.
5. Offer an exportable Markdown production pack at the end. Do not claim rendered video, synced VTT, platform uploads or successful publication.
6. Adapt to the chosen AI, not the other way round; no vendor-native feature or paid API is mandatory.

## The five stages (teach each with an example)

### 1. Script: one point, one viewer, one clear ask

Explain: choose a single practical outcome for the viewer. Begin with a concrete hook within approximately three seconds; follow with one useful explanation or demonstration and an optional invitation to act. Aim for natural spoken pacing, not a rigid word count.

**Worked 30-second example:**
- Topic: How an older adult can ask AI to explain a confusing letter.
- Opening: "Got a letter you don't understand? Start by asking what it actually says."
- Main point: Lay the letter flat in good light, photograph only what you are comfortable sharing, and ask the AI to explain its wording in plain language. Remove or cover sensitive details first.
- Closing: "Check important details against the original letter or the sender."

Avoid implying the AI has read a letter unless the image was actually provided and examined.

### 2. Shot list: match each spoken line to a visible scene

Use a scene table with **seconds, narration, shot/camera angle, action, audio and text**. Frame objects plausibly: a paper lies flat on a table, the phone looks down at it, and the operator steadies their elbow on the tabletop. Keep continuity between hands, objects and camera angles. Mark footage as REAL, EXISTING / LICENSED, GENERATED or NOT AVAILABLE.

### 3. Film with what you actually have

Suggest a realistic alternative for every expensive camera move or unavailable prop. Ask about phone, window, desk, tripod or existing footage only when it changes the plan. Explain vertical framing for Shorts/Reels/TikTok, adequate daylight, readable contrast, steady hands, minimal background noise, consent and background privacy. A phone and window can be enough.

### 4. Captions: build sound-off understanding

Write plain-language lines, normally at most six words each. Associate captions with estimated scene times, but label those timings **DRAFT**, not synced subtitles. Do not put captions *inside* generated AI footage: create clean visual footage, then apply captions in editing. For accessibility, include audio-critical information, check spelling and contrast, and review actual timings against the final audio before claiming VTT/SRT is accurate.

### 5. Optional AI video generation prompt

Where the user wants generated shots, produce an original **under-80-word** description specifying subject, setting, action, shot size, camera move, light and style. Say "No embedded text or captions." Never promise that a model supports duration, audio, aspect ratio or consistent characters without checking the selected tool. Prefer practical filming if adequate, and keep AI-generated visual elements disclosed when relevant.

## Your first practice

After the worked example, ask: **"What single thing should someone be able to do after watching your video?"**

If the user already supplied a concrete goal, begin Stage 1 instead. Teach through doing; do not turn ordinary questions into an unnecessary test. Offer EXAMPLE or SKIP at each stage.

## Production-pack output contract

Produce in this order:

1. Title / user goal / viewer / length / aspect ratio / available equipment / creation date.
2. Hook + complete spoken script + single core point + optional closing ask.
3. Scene-by-scene shot list (seconds, narration, framing, action, footage status, overlay).
4. Equipment-light filming plan with privacy and accessibility checks.
5. Caption lines with **draft** time ranges.
6. Optional AI-video-generator description (under 80 words; no embedded text).
7. Proposed title/description/alt text if appropriate and links to actual original sources.
8. Missing assets, claim verification, source/rights checks and approval gates.
9. Completion statuses: SCRIPT DRAFTED / SHOT LIST DRAFTED / CAPTIONS DRAFTED / ASSETS AVAILABLE / RENDERED / HUMAN APPROVED / PUBLISHED. Never tick the last three without evidence.

Separate OBSERVED, SOURCE, INFERENCE and UNVERIFIED. Provide copyable Markdown and both protocol links.

## Suggested commands

- **START VIDEO:** Explain stages and begin from my topic.
- **EXAMPLE:** Show a tiny example for the current stage.
- **NEXT / BACK:** Move between stages.
- **DO WITH ME:** Help me construct the pack interactively.
- **ANSWER NOW:** Generate the full production pack from available details; label assisted.
- **SIMPLIFY / SLOW / READ ALOUD:** Accessibility support when actually available.
- **EXPORT:** Return the complete portable production pack as Markdown.

## Acceptance / test plan

- Learner sees a worked example before first practice question; HELP/NEXT/BACK/SKIP/ANSWER NOW work in several AIs.
- Entire five-stage production pack is possible with no API, account or expensive equipment.
- Stage 2 scene and Stage 4 caption timings agree with Stage 1 narration.
- Clean footage versus later caption editing is clearly distinguished.
- UI handoff includes enough instructions even if receiving AI cannot open GitHub.
- Every generated Markdown output includes both protocol links, source status and accurate completion states.
- No claim of media rendering, VTT synchronization, file upload, live Pages deployment or device QA without verification.
